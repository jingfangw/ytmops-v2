## Overall Impression

A strong, committed design system dragged down by flow and edge-state handling, not by its looks. The visual layer is ~85% immaculate; the score is pulled down by the sync failure path, silent data loss in the PDF, and stock-color leaks. The single biggest opportunity: make the high-stakes moments (sync failure, zero-order mornings, PDF export) as trustworthy as the resting state already is.

## What's Working

1. **A genuinely committed design system, not a template** — mono uppercase labels on every meta string, flat hairline sections, one consistent `.delivery-pill`/`.count-badge` language. Reads as a paper form that syncs, exactly as DESIGN.md intends.
2. **Persistent freshness signals over ephemeral ones** — `Last synced: HH:MM`, the delivery-date pill, and Singapore-safe `getTomorrowDate()` keep the two facts staff must trust (how fresh, which day) always on screen.
3. **Clean live-vs-history separation** — entering history shows a banner, hides Sync + Live, offers one-tap "← Today", and suppresses realtime re-renders while browsing, structurally preventing acting on a past date as if live.

## Priority Issues

**[P0] Picking-List PDF silently drops rows past 25 per outlet.**
- Why: `_doPicklistPDF` fixes `MAX_ROWS=25`; an outlet with 30 SKUs prints only 25, rows 26–30 silently discarded with no "+N more". The PDF is the artifact that loads the truck — silent omission = items not picked, caught only when an outlet complains. Data loss disguised as a clean document.
- Fix: continue the outlet into a second box/column, size the box to row count, or at minimum print a bold `+N more — see app` row. Never render a truncated list that looks complete.

**[P0] Sync failure is hostile, and a failed sync can leave the day wiped.**
- Why: failure = 4s English `Sync failed: <err.message>`, no retry, not announced to SR. Worse, `syncOrders` does `orders.delete()`/`order_lines.delete()` for the date *before* the chunked inserts — if any insert throws, the date is left partially/fully wiped with only a toast. Boot-time `syncOrders(true)` swallows failures entirely.
- Fix: (1) persistent translated error banner with a **Retry** button; (2) stage-and-swap or upsert so a failed sync never destroys existing data; (3) surface silent-sync failure with a "showing last saved data" indicator instead of a green Live dot.

**[P1] "Not synced yet" shown after a genuinely successful zero-order sync.**
- Why: `renderSummary`/`renderByOutlet` show `notSynced` whenever `orders.length===0`, conflating "never synced" with "synced, zero orders". Early morning this reads as broken when it worked.
- Fix: branch on `lastSyncTime` — if synced, show translated "No orders yet for {date}"; reserve "Not synced yet" for never-synced.

**[P1] Misused state signals: fake "Live" dot + red used for a non-error.**
- Why: `.sync-dot` pulses green via pure CSS, unbound to `realtimeChannel` — it lies when the socket is dead (the anti-pattern PRODUCT.md already removed once). "Not yet ordered" uses the red/error palette, but a pending order is not an error; the `signal-orange` token — defined specifically to "stand apart without reaching for red's error connotation" — is unused. A 6am board of all-pending outlets looks like a wall of errors, dulling red's meaning.
- Fix: bind the dot to actual channel state (green only on `SUBSCRIBED`) or remove it; recolor "Not yet ordered" to `signal-orange`, keep red for true failures.

**[P2] Bilingual coverage collapses in JS-rendered and exported strings.**
- Why: hardcoded English in the sync toasts, `Viewing history:` toast, history-banner labels, "Loading…", raw Supabase login errors, and **the entire PDF** (`DAILY ORDER SUMMARY`, `PICKING LIST`, `Product`, `Qty`, `Synced:`, `Delivery:`, `items`). A 中文 operator exports an English document. `stripChinese()` (no-font fallback) can blank a Chinese-only product name to an empty row.
- Fix: route every user-facing string through `T[lang]`, including PDF headers/labels and toasts; map Supabase auth errors to translated copy; transliterate/keep a Latin SKU rather than emptying a cell.

**[P2] Accessibility of custom controls + touch ergonomics.**
- Why: `user-scalable=no, maximum-scale=1.0` disables pinch-zoom (WCAG 1.4.4); tabs/toggles are plain buttons with no `role="tab"`/`aria-selected`/`aria-pressed`; toast isn't `aria-live` (sync result inaudible to SR); login `<label>`s aren't linked to inputs; no `prefers-reduced-motion` guard on `pulse`/`spin`; tap targets (tabs 7×16, sub-tabs 6×14, lang 5×12) are well under 44px for gloved/hurried use.
- Fix: remove the zoom lock; add ARIA roles/state; make the toast `aria-live`; associate labels; add reduced-motion; bump controls to ≥44px.
